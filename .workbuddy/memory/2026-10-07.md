# 2026-10-07

## 项目整体评估（用户要求：以 10 年经验开发者/面试官视角）

项目已从 9/20 的单一 Agent 演进为：LLM 编排 + 工具 + 长期记忆(偏好/待办/笔记) + 会话压缩 + trace 观测 + FastAPI + 前端 + CLI。半个月内新增 api/、cli/、memory 拆包、tools 增 web_search/fetch_url/note、vision 图片识别、和风天气(JWT) 等。

**最严重发现（P0 正确性）**：tools 通过模块级 `_context`（tools/context.py）惰性取 store；`Agent.init()` 里 `set_context` 会 `_context.update()` 覆盖全局；API 的 `AgentPool` 多 session 并存 → 工具实际读写"最后一个 init 的 agent"的 store，跨 session 串数据。context.py 注释自己写了"不做线程隔离，单进程单线程"，但这个假设已被多 session 的 FastAPI 打破。

其它问题（按优先级）：
- 无 git，改动不可追溯；9/20 加的 MAX_CONTEXT_TOKENS 预判/KEEP_RECENT_TURNS 上限被人删了但常量留着成死代码，重复赋值。
- 测试套件无法收集：test_trim_messages import 已被注释的 `_estimate_tokens_full`；test_note_summary import 已删的 `get_last_long_input`。比 9/20 的 26 failed 更糟。
- run.py 917 行 God class + 调试残留（[DIAG] 每次调用打 warning、main() 打 [DEBUG] QWEATHER_*、`_stream_main_call` 里重复的两段 `if not chunk.choices`）、硬编码天气 stub 与 tools/builtin.py 真实现并存、SUMMARY_MAX_RETRIES 死代码。
- backend/core/ 六个空文件（harness/llm/memory/sandbox/executor/tools/base）——被放弃的抽象层。
- requirements.txt 只有 pytest 三个包，无运行时依赖。
- keys/qweather_ed25519.pem 私钥进源码树；.env 的 API_TOKEN 为空（鉴权形同虚设）；两个 DB 文件 + DEFAULT_DB_PATH 相对路径（cwd 敏感）。
- 全局 last_image_description/last_user_content 传递请求数据（并发串）。
- vision.py 前 72 行是注释掉的旧版；schema 迁移是 ad-hoc ALTER TABLE 无版本化。

优点：trace 可观测性（嵌套 step/墙钟 vs 自耗时/ttft/reasoning_chars）、阈值可达性思维、溢出双路兜底、工具注册中心（pydantic→JSON Schema + 统一 invoke + 异常兜底）、增量摘要 + 短期/长期记忆分离。
